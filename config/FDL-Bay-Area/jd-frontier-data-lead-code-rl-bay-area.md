# Frontier Data Lead, Code + RL Environments (Bay Area)

## Source roles

- [Frontier Data Lead, Code - US](https://careers.turing.com/job/5822272004)
- [Frontier Data Lead, RL Gyms - US](https://careers.turing.com/job/5822287004)

Both live roles were retrieved from Turing's public careers API on April 8, 2026.

## Shared role spine

Both roles describe the same core job shape:

- A hands-on frontier technical lead mapped directly to one or more AI lab customers
- Owns delivery end to end: scope, quality, throughput, team build-out, and client communication
- Builds datasets, environments, evals, automation, and internal tooling that improve frontier models
- Operates like a startup GM for a technical post-training project, not a narrow researcher or pure people manager
- Needs enough operational leadership to hire, train, QA, and coordinate engineers, researchers, domain experts, and data creators

## Code role emphasis

The Code role adds specific emphasis on:

- Coding agents and software-engineering environments
- SWE-task post-training and proof-of-value fine-tuning
- Benchmarks and evals for real software-development workflows
- Internal tooling such as repo sandboxing, unit-test generation, validation scripts, and customer-facing eval dashboards
- Fluency in Python plus at least one major systems language

## RL Gyms role emphasis

The RL Gyms role adds specific emphasis on:

- RL environment lifecycle ownership
- Reward and verifier design
- Task generation, seed data, schemas, APIs, and long-horizon workflow realism
- Simulating real business or consumer applications for tool-use agents
- Proof-of-value via RL fine-tuning or eval reports on frontier models

## Merged sourcing interpretation

For sourcing, the most faithful merged target is not "someone equally deep in every surface area." The strongest target is:

- A senior hands-on builder-leader with a primary anchor in either coding-agent/SWE evaluation work or RL-environment/post-training work
- Plus enough adjacent depth in the other lane to credibly lead the full lifecycle of a frontier data project
- Plus strong systems judgment, process design, and lab-facing communication

This means the brief should save people who clearly fit one of these patterns:

1. Coding-agent / SWE-evals leaders who also understand environment design, verifiers, task generation, and proof-of-value model improvement
2. RL environment / post-training leaders who also understand code tasks, repo-level evaluation, and software-engineering workflows
3. Agent-infrastructure builders who created browser-use, tool-use, or MCP-style environments with strong quality systems and hands-on leadership

This means the brief should avoid over-saving:

- Generic AI application builders who shipped copilots or workflows but never touched post-training, environments, or evaluation methodology
- Pure infra or MLOps profiles without model-improvement or data-quality ownership
- Pure people managers, product leaders, or annotation operators
- Classical RL or robotics researchers with no visible bridge into LLM agents, tool-use environments, or scalable evaluation systems
